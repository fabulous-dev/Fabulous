## 5. Limits / unresolved

- The solution could not be built directly (the `maui-tizen` workload is missing on the runner), so sources were type-checked against NuGet reference assemblies instead. This is a source-level check, not a runtime test.
- FCS does not report computation-expression builder members (`Yield`, `Combine`, `Run`, `Bind`, `For`, ...) or enumerator patterns (`for x in diffs`) as symbol uses, so these implicit uses are **not captured** (e.g. `CollectionBuilder.Run/Yield` behind every `VStack() { ... }`). Only extension-method calls are flagged implicit.
- Uses that exist only through type inference (no written symbol) are absent.
- Namespace-level `Fabulous` references (`open Fabulous`) are excluded.
- `Fabulous.MauiControls.Tests` and `src/neutral/Fabulous.Tests` are excluded.
